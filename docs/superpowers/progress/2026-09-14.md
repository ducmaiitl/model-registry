# 2026-09-14 — model-registry v0.1.0: built, reviewed, packaged, documented

## Headline

The registry went from an empty directory to an installable library with a
pinned catalog of every model robo-be runs, in eight commits over
2026-09-10 → 09-14. The facade's central claim — consumers never touch the
backend — was tested the hard way: the artifact store was swapped from MinIO
to GCS mid-way and **zero lines of `client.py` or any consumer changed**.

Two production-relevant findings fell out of building it, neither of which
anyone was looking for.

## Findings worth remembering

**gipformer is a latent outage in robo-be.** Upstream commit `29621ec8`
(2026-08-21, *"Remove legacy epoch-35-avg-6 filenames"*) deleted every file
`asr_gipformer.py` requests by name. `hf_hub_download` 404s on any host without
a pre-August cache; production runs only because `model_cache` is stale. The
catalog pins `ba00dad1` — the last revision whose filenames match — so the
registry version is faithful to what production actually has. The loader fix is
Phase 1 / Task 3 of the plan.

**Interrupting an upload left empty model shells.** Two catalog imports were
killed mid-upload (correctly — nobody wanted 21 GB on a laptop). Both left a
registered model with zero versions plus a `RUNNING` run with partial artifacts,
because `register()` created the model *before* uploading. Reordered; a test
now asserts a failed upload leaves nothing. Orphan-run GC is Phase 5.

**Two "works by accident" bugs the review caught.** `models.yaml` shipped with
duplicated `exclude:` keys — PyYAML silently keeps the last one — now rejected
by a strict loader. And two tests stubbed `reg._mlflow.log_artifacts` directly;
since `reg._mlflow` *is* the global module, the stub leaked into six later tests.
Both now go through `monkeypatch`.

**HF Hub throttles anonymous traffic hard enough to stall metadata calls.** A
pure-API dry-run exceeded two minutes without a token. A read token fixed it;
the token is an import-time credential only and never reaches a consumer.

## Decisions taken (details in the spec's §15)

- GCS over MinIO — user, 2026-09-14. The registry runs on GCP; leaving Google's
  managed STT/TTS APIs does not mean leaving GCP storage.
- No model downloads, loading, or benchmarking on the development laptop; unit
  tests and dry-runs only. Heavy work runs elsewhere.
- Deployment topology is out of scope for this repo's documents.
- Consumers depend on `mlflow-skinny`; full `mlflow` is a `[dev]` extra.
- Catalog re-runs never move an alias on a skip.
